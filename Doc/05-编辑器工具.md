# 编辑器工具

## 范围

本篇覆盖：

- `Assets/YFramework/Editor`
- `Assets/YFramework/UI/Editor`

这些代码运行在 Unity Editor 中，不属于玩家运行时逻辑。

## 总体定位

YFramework 的编辑器层主要做三类事：

- 自动化生产或生成代码
- 资源导入与命名约束
- 提升 UI / 场景编辑效率

其中最核心的一类已经单独成篇：

- `02-AutoBind机制.md`

本篇更多关注 AutoBind 之外的编辑器功能。

## 1. 场景自动保存

文件：

- `Assets/YFramework/Editor/AutoSaveScene/AutoSaveWindow.cs`
- `Assets/YFramework/Editor/AutoSaveScene/XPAutoSave.cs`

### `AutoSaveWindow`

提供一个简单的 EditorWindow，用来配置：

- 是否自动保存
- 时间间隔
- 是否输出消息

当前配置通过项目内 `ScriptableObject` 资产持久化：

- `Assets/YFramework/Editor/AutoSaveScene/AutoSaveSettings.cs`
- `Assets/YFramework/Editor/AutoSaveScene/AutoSaveSettings.asset`

`AutoSaveSettings.asset` 随项目提交，用于团队共享自动保存默认配置。

入口菜单：

- `YFramework/AutoSaveScene`

### `XPAutoSave`

特点：

- `[InitializeOnLoad]`
- 静态构造时注册 `EditorApplication.update`
- 定时调用 `EditorSceneManager.SaveScene(nowScene)`

这套机制适合个人开发或原型阶段，目标很明确：防止编辑器里长时间未保存。

### FACT

- `AutoSaveWindow.autoSaveScene`、`AutoSaveWindow.intervalTime`、`AutoSaveWindow.showMessage` 当前读写 `AutoSaveSettings.asset`
- `XPAutoSave` 继续通过 `AutoSaveWindow` 的静态访问入口读取自动保存配置
- `yf_autosave_config` MCP 工具继续通过 `AutoSaveWindow` 的静态访问入口查询和设置自动保存配置

### CURRENT STRATEGY

- 自动保存配置作为项目内 Editor `ScriptableObject` 资产提交，供团队共享默认参数
- 自动保存配置资产不存在时，由编辑器侧代码按默认值创建

### KNOWN ISSUES

- 当前未记录自动保存配置持久化相关的已知问题

## 2. 资源导入规则

目录：

- `Assets/YFramework/Editor/ImportResSeting`

### `AudioSetting`

文件：

- `Assets/YFramework/Editor/ImportResSeting/AudioSetting.cs`

作用：

- 作为 `AssetPostprocessor` 处理导入音频
- 根据音频时长选择 `AudioClipLoadType`

当前策略：

- 小于 1 秒：`DecompressOnLoad`
- 否则：`Streaming`

### `InputResourcesSetting`

文件：

- `Assets/YFramework/Editor/ImportResSeting/InputResourcesSetting.cs`

定位：

- 资源导入命名检查器

当前可见能力：

- 在指定路径下检查导入资源名是否符合正则规则
- 若不符合，记录错误并尝试弹出命名管理窗口

注意：

- 文件中一些贴图导入设置逻辑目前被注释掉了
- 因此它更像一个“预留中的导入规范入口”

### `NameMgrWindow`

文件存在于同目录，用于承接命名检查失败后的编辑器交互。
从整体结构看，它属于资源规范化流程的一部分。

## 3. 通用编辑器工具

目录：

- `Assets/YFramework/Editor/Utility`

### `AssetDataBaseUtility`

定位：

- 对 `AssetDatabase` 相关操作做包装或简化

### `LogUtility`

定位：

- 编辑器日志或输出相关工具
- `ClearConsole` 通过反射调用 Unity Editor 的 `LogEntries.Clear`
- 当前实现会在反射方法不存在时跳过调用，避免空引用异常

这两个文件的角色更偏“辅助型工具箱”，是编辑器开发时的便捷层，不是主架构入口。

## 4. UI 编辑器支持

目录：

- `Assets/YFramework/UI/Editor`

### `MenuOptions`

文件：

- `Assets/YFramework/UI/Editor/MenuOptions.cs`

作用：

- 在 Unity `GameObject` 菜单下新增 YFramework UI 项
- 自动创建或复用 Canvas
- 自动创建 EventSystem
- 生成自定义 UI 控件对象

当前菜单项包括：

- `GameObject/YFramework/UI/PolygonColliderImage`
- `GameObject/YFramework/UI/CircleImage`

这说明 YFramework 不只是提供运行时控件，也把控件创建流程编辑器化了。

### `CricleImageEditor`

文件：

- `Assets/YFramework/UI/Editor/CricleImageEditor.cs`

作用：

- 为 `CircleImage` 提供自定义 Inspector
- 在编辑器里暴露 `showPercent` 与 `segments`

这类脚本的价值在于让自定义控件更容易调参数，而不用只依赖默认 Inspector。

## 5. 与运行时代码的协作关系

编辑器工具层和运行时层的关系很清晰：

- 编辑器层负责生成、配置、约束
- 运行时层负责实际表现与逻辑

例如：

- `AutoBindEditor` 生成字段，运行时组件持有这些字段
- `CricleImageEditor` 提供面板，`CircleImage` 真正画图
- 导入设置器规范资源，运行时脚本消费资源

## 6. 当前边界

### 1. 很多工具更偏个人工作流增强

例如自动保存、命名检查、快捷建 UI，都明显带有“提升作者工作效率”的目的。

### 2. 资源导入体系并不算完整

有一些方向已经存在入口，但仍然可以继续扩展，例如：

- 图片导入规范
- 更细颗粒度的命名规则
- 批量修复工具

### 3. 编辑器层分散但职责还算明确

并没有形成一整套统一 Editor Framework，而是按需求放在不同小目录下。

## AI 修改建议

如果你要改编辑器逻辑，优先先判断：

- 是生成代码？优先看 AutoBind
- 是导入资源规则？优先看 `ImportResSeting`
- 是场景工作流问题？优先看 `AutoSaveScene`
- 是 UI 创建体验？优先看 `UI/Editor`

还要特别注意：

- 编辑器脚本的命名空间与运行时脚本不同
- 不要把 `UnityEditor` 依赖带进运行时代码
- 如果修改生成器类，最好同步检查测试样例输出是否还能成立

## 7. UnityMCP 团队接入

### FACT

- `Packages/manifest.json` 已加入团队共享依赖 `com.coplaydev.unity-mcp`
- 当前接入方式使用官方 Git 包地址：`https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main`
- UnityMCP 属于编辑器侧能力，接入后由 Unity Editor 负责导入并在编辑器内提供 `Window/MCP for Unity`
- 项目侧推荐的 MCP 连接方式是本地 HTTP：`http://localhost:8080/mcp`
- `Assets/YFramework/Editor/YFramework.Editor.asmdef` 已添加对 `MCPForUnity.Editor` 的程序集引用
- `Assets/YFramework/Editor/MCP/YFrameworkMcpTools.cs` 包含第一批 YFramework 自定义 MCP 工具
- 自定义工具利用 MCP 包的 `[McpForUnityTool]` 反射发现机制，无需额外注册

### 前置条件（每台机器首次使用前必须完成）

#### 1. 系统级依赖

| 依赖 | 版本要求 | 安装方式 | 验证命令 |
|---|---|---|---|
| Python | >= 3.10 | [python.org](https://www.python.org/downloads/) 或包管理器 | `python --version` |
| uv / uvx | 最新版 | [官方安装脚本](https://docs.astral.sh/uv/getting-started/installation/) | `uv --version` |
| Unity Editor | 2021.3+ | Unity Hub | 打开项目后自动检查 |

#### 2. MCP 包解析（首次 clone 后）

```
1. 用 Unity Editor 打开 YFramework 项目
2. 等待 Unity 自动从 Git 拉取 com.coplaydev.unity-mcp 包
3. 确认 Window 菜单中出现 “MCP for Unity” 入口
4. 若长时间未出现，检查 Packages/packages-lock.json 是否生成对应条目
```

#### 3. MCP 服务启动

```
1. Unity 菜单：Window > MCP for Unity
2. 点击 “Auto-Setup” 完成自动配置
3. 确认 “Unity Bridge” 状态为 Running
4. 记录显示的 Unity Port 和 MCP Port（默认 8080）
```

#### 4. MCP 客户端连接（本机自管，不提交仓库）

**Claude Code：**
```bash
claude mcp add unityMCP --url http://localhost:8080/mcp
```

**Codex：**
```bash
codex mcp add unityMCP --url http://localhost:8080/mcp
```

**Cursor / VS Code / Windsurf：**
在 MCP for Unity 窗口中选对应客户端，点击 “Auto Configure”。

### CURRENT STRATEGY

- UnityMCP 作为项目共享编辑器依赖纳入 `Packages/manifest.json`
- YFramework 自定义 MCP 工具放在 `Assets/YFramework/Editor/MCP/` 下，通过 `YFramework.Editor` 程序集编译
- 每个团队成员的 MCP 客户端连接配置保持本机自管，不写入仓库
- `Packages/packages-lock.json` 的实际锁定结果依赖 Unity Editor 对该 Git 包完成一次成功解析

### 自定义 MCP 工具清单

| 工具名 | 功能 | 参数 |
|---|---|---|
| `yf_autosave_config` | 查询/设置场景自动保存配置 | action(get/set), enabled, interval_seconds, show_message |
| `yf_get_framework_info` | 获取 YFramework 元信息（版本/模块/AutoBind规则） | category(all/version/modules/autobind) |
| `yf_autobind_generate` | 触发 AutoBind 代码生成 | target(GameObject名/路径/InstanceID), mono_type(MonoBehaviour类型名) |

### 添加新工具的方法

1. 在 `Assets/YFramework/Editor/MCP/` 下新建 `.cs` 文件
2. 类上加 `[McpForUnityTool(“your_tool_name”)]` 属性
3. 内部类 `Parameters` 用 `[ToolParameter]` 声明参数
4. 实现 `public static object HandleCommand(JObject @params)` 或 `public static Task<object> HandleCommand(JObject @params)`
5. 返回 `new SuccessResponse(message, data)` 或 `new ErrorResponse(code)`
6. Unity 重新编译后自动发现，无需任何注册步骤

### KNOWN ISSUES

- 按 UnityMCP 官方说明，启动服务前置条件仍需本机安装 `Python 3.10+` 与 `uv`
- `Packages/packages-lock.json` 可能因 Unity 实例冲突而无法刷新，需关闭其他 Unity 实例后重试
- YFramework 自定义 MCP 工具依赖 `YFramework.Editor` 程序集编译成功，若项目存在编译错误则工具不可用
- 首次 clone 后新成员需要完成 “前置条件” 中所有步骤方可使用 MCP 工具
- `yf_get_framework_info` 当前返回的 `runtime_modules` 中仍包含 `Kit/Net (TCP/UDP)` 旧描述，实际网络目录已迁移到 `Assets/YFramework/Network`
